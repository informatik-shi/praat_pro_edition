# Встроенный Script IDE и debugger

База: Praat 7.0.02, upstream `6f3da9ef1d8cce0d5684afc104d02888dfc71b25`.
Windows UI реализован без внешнего редактора и дополнительных библиотек.

## Модули и зависимости

- `ScriptEditor` сохраняет создание, открытие, сохранение, формы параметров и обычный Run Praat.
- `GuiText` включает системный Msftedit RichEdit только по флагу `GuiText_SCRIPT_IDE`.
  Остальные текстовые редакторы продолжают использовать исходный control.
- `ScriptSyntax` — лексер для отображения. Он не исполняет и не преобразует скрипт.
- `ScriptDebugger` — состояние, решения об остановке, извлечение значений, безопасный Watch.
- `WinScriptEditor` — оконный controller, gutter, TOM anchors, вкладки, форматирование и event pump.
- `Interpreter` знает только необязательный указатель на `ScriptDebugger`.

## Исполнение и source line

В основном цикле `Interpreter_resume` observer вызывается непосредственно перед
выполнением реальной инструкции. При обычном Run указатель равен null.
Номер строки берётся из `Interpreter::lineNumber`, не из таймера UI.
Пустые строки и комментарии не вызывают остановку. Структурные инструкции
(`endproc`, `endfor` и др.) остаются возможными остановками: это реальные
итерации upstream interpreter. Пропущенные ветви не исполняют hook.
Continuation-строки объединяются штатным интерпретатором с сохранением пустых
позиций; breakpoint ставится на первую строку инструкции.

Для include в первой версии необходимо выполнить Convert > Expand include files.
Debugger явно отклоняет неразвёрнутый include, чтобы не показывать ложные номера
строк. Обычный Run обрабатывает include как upstream. Отдельной карты нескольких
исходных файлов пока нет.

## Состояния и шаги

`Idle → Running → Paused → Running`; Stop переводит в `Stopping`, затем
`Finished`; необработанная ошибка — в `Error`. Новый F5 начинает новую сессию.

- Continue: следующая реально достигнутая точка останова.
- Into: следующая исполняемая инструкция, включая тело процедуры.
- Over: следующая инструкция с `callDepth <=` глубины остановки.
- Out: следующая инструкция с меньшим `callDepth`.
- Breakpoint внутри вызываемой процедуры имеет приоритет и может прервать Over/Out.
- Stop вызывает штатный `Interpreter_stop` на границе инструкций.

Внешняя ошибка перехватывается после формирования штатной диагностики Praat;
сохраняются сообщение и номер строки, редактор прокручивается к ней. Оригинальный
диалог ошибки также сохраняется.

## GUI и lifetime

Выполнение и GUI остаются в одном потоке. Hook опрашивает события примерно раз
в 30 мс; paused-loop ожидает сообщения с тем же интервалом. Watch, вкладки и Debug
работают во время паузы. Редактирование исходника и остальные меню/окна Praat
временно отключаются, чтобы не допустить повторный запуск и изменение живого
состояния интерпретатора. Закрытие активного редактора сначала запрашивает Stop.
После завершения окна снова доступны.

Указатель `current` заимствован из принадлежащего редактору InterpreterStack;
перед очисткой стека при новом обычном запуске и при смене файла он сбрасывается.
Новый debug-start также очищает предыдущий current. Формы параметров используют
штатный путь Praat; если форма отменена, Stop сбрасывает ожидающую сессию.

Длительная отдельная команда C/C++ не прерывается внутри команды. Вложенный
`runScript` использует другой interpreter и проходит как атомарный вызов;
Step Into реализован для процедур текущего скрипта. Асинхронные pause/demo-сценарии
не входят в проверенную область первой версии; для них используйте обычный Run.

## Variables, Watch, Call Stack

Variables читает настоящую `variablesMap`: number, string, numeric vector,
numeric matrix, string vector. Значения сортируются по имени. Точка в имени
означает procedure-local storage; текущая процедура помечается local, остальные
procedure, остальные имена global. Это семантика Praat, а не введённые C++ scopes:
рекурсивные вызовы разделяют локальные переменные одной процедуры.

Превью ограничены: строка 160 символов, vector 8 элементов, matrix размеры и
6 элементов первой строки, string vector 4 элемента. Отдельный табличный inspector
пока не реализован; функции получения представления отделены от UI.

Watch использует существующий Formula evaluator только на паузе. Разрешены
существующие переменные, арифметика/логика, константы и явный список чистых
математических/строковых функций. Неизвестные символы, command/file/random/
stopwatch-вызовы, подстановки и вызовы процедур отклоняются до вычисления.
Это намеренно ограниченное подмножество Formula. Выражение ограничено 2048
символами, список — 100 записями; массивы смотрятся через имя переменной.
Watch не изменяет переменные, но сложное допустимое выражение может занять время.

Call Stack использует `callDepth`, `procedureStackNames` и `callStack` самого
интерпретатора. Показаны текущая строка и места вызова родителей. Выбор отдельного
frame для вычисления Watch не поддерживается.

## Редактор и breakpoints

RichEdit хранит только текст; gutter — отдельное дочернее окно. TOM collapsed
ranges привязаны внутри строки и следуют за вставками/удалениями выше неё.
Удаление самой строки может объединить точки на соседней строке. F9 и клик
используют реальные координаты строк control. Точки сохраняются в
`%LOCALAPPDATA%\PraatCustom\breakpoints\<hash-path>.txt` при изменении и закрытии.
Для несохранённого файла постоянного хранилища нет; при переименовании файла
используется новая запись. Watch пока сохраняется только в текущем окне.

Подсветка обрабатывает видимые строки и небольшой запас, кэш ограничен 256
строками. Таймер 100 мс обнаруживает изменения; неизменённые строки не
форматируются повторно. TOM Undo suspend/resume исключает подсветку из undo.
Selection, scroll position и modified flag сохраняются. Unicode текст RichEdit
преобразуется между UTF-16 и char32; CR нормализуется штатными средствами Praat.
Раскраска одной сверхдлинной строки ограничена 65534 UTF-16 units. Ln/Col
использует позиции UTF-16 (символ вне BMP занимает два столбца).

Цвета собраны в `EditorTheme`; проверена светлая тема. Динамический dark mode
не реализован. Высота панели фиксирована, основное окно можно увеличивать.

## Проверки

`scripts/test-debugger.sh` связывает тестовый executable с теми же библиотеками
Praat и проверяет настоящие остановки, глубины, значения, Watch, ошибки и Stop.
`scripts/test-windows.sh` запускает штатные test и dwtest с FULL TRUST только
для этих тестовых fixtures. Результаты GUI и ограничения: `docs/acceptance.md`.
