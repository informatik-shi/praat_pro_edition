# Анализ по числу отсчётов: SpectrogramS

## Длина анализа в Sound View & Edit

1. Выделите Sound и откройте **View & Edit**.
2. В меню **Spectrogram** выберите **Analysis length in samples…**.
3. Включите **Use exact sample counts** и задайте **Analysis length (samples)**.
   Под полем сразу показывается соответствующая длительность в миллисекундах
   и частота дискретизации звука. **Time step (samples)** — расстояние между
   соседними кадрами; для него тоже показываются миллисекунды.
4. **Transform size (samples; 0 = analysis length)** задаёт длину преобразования.
   Ноль означает ровно длину анализа. Для степени двойки используется FFT,
   для остальных длин — прямое ДПФ по формуле. Заданная вручную длина
   не должна быть меньше длины анализа. Метод и частотный шаг видны сразу в форме.
5. Нажмите **Apply** или **OK**: спектрограмма пересчитается. Форма окна
   выбирается в **Advanced spectrogram settings…**.

Это физическое число отсчётов: **256 означает ровно 256** для всех форм окна,
включая Gaussian. У штатного Praat параметр Gaussian в секундах обозначает
половину физической длины, а старый расчёт дополнительно округляет число
отсчётов. Новый режим не применяет это округление. Нечётные длины тоже допустимы.

Примеры для 256 отсчётов:

| Частота дискретизации | Длительность |
| --- | --- |
| 22050 Гц | 11.609977 мс |
| 44100 Гц | 5.804989 мс |
| 48000 Гц | 5.333333 мс |

Формула: `мс = 1000 × число_отсчётов / частота_дискретизации`.
Дополнение нулями для FFT улучшает шаг частотной сетки, но не добавляет
отсчётов сигнала в окно анализа. Частотный шаг равен `Fs / transform_size`.
Без явно заданной большей длины нули не добавляются.

Настройка относится к вычисляемому анализу Sound/LongSound; уже загруженные
SmartSpectrogram, Spectrogram и SpectrogramS сохраняют свои рассчитанные значения.
Для них изменение длины требует нового расчёта из Sound.
Настройки динамического диапазона и цветов продолжают работать.

Для возврата к обычному режиму снимите **Use exact sample counts**.
Изменение длины окна в секундах в обычном **Spectrogram settings…** тоже
возвращает обычный расчёт. Если меняется только диапазон частот/дБ и длина
остаётся прежней, режим отсчётов сохраняется.

**Extract visible spectrogram** публикует SpectrogramS, когда активен новый
режим. **View spectral slice** в этом режиме берёт ближайший рассчитанный
кадр и использует его точное окно, включая при выделенном временном интервале.

## Новый объект SpectrogramS

Выделите Sound и выберите **To SpectrogramS…**. Поля:

- **Analysis length (samples)** — точная длина окна, минимум 2.
- **Time step (samples)** — целое число отсчётов между кадрами, минимум 1.
- **Maximum frequency (Hz)** — верхняя частота, не выше половины Fs.
- **Transform size (samples; 0 = analysis length)** — длина преобразования;
  ноль означает длину анализа, без округления.
- **Window shape** — square, Hamming, Bartlett, Welch, Hanning, Gaussian.

Обрабатываются только полные окна. Первый кадр начинается с первого отсчёта
Sound; время кадра — середина его окна. Последовательные окна сдвигаются
на заданный шаг. В Sound Editor при масштабировании сохраняется сетка кадров
исходного Sound. Для многоканального звука усредняются мощности каналов:
противофазные каналы не гасят спектр друг друга.

Значения хранятся в том же соглашении о мощности FFT и энергии окна, что
у стандартного Spectrogram. Спектральные отсчёты идут от 0 Гц до указанной
верхней частоты с шагом `Fs / transform_size`, включая Nyquist при полном диапазоне.

SpectrogramS хранит частоту дискретизации источника, длину окна, шаг кадров,
длину преобразования и форму окна. Они доступны через **Info** и команды **Get analysis
length in samples**, **Get analysis length in milliseconds**, **Get source
sampling frequency**, **Get time step in samples**, **Get transform size in samples**,
**Get transform method**. Старое имя **Get FFT size in samples** тоже принимается.

**View & Edit** открывает обычный редактор спектрограммы. Можно выделить
**Sound + SpectrogramS** и нажать **View & Edit** для совместного просмотра
со стандартными анализами Sound. SpectrogramS поддерживается и в общем
**View & Edit selected** со звуком и FrequencyTrajectories, включая TextGrid
и SmartSpectrogram при необходимости. Обычный Spectrogram и SpectrogramS
занимают один и тот же выбранный спектральный слой: выбирайте один из них.

Сохранение — штатные **Save as text file…**, **Save as binary file…**;
чтение — **Open → Read from file…**. Нативный файл сохраняет параметры анализа.

Ограничения для отзывчивости: максимум 1048576 отсчётов в окне/преобразовании и
20 миллионов значений в объекте. При превышении увеличьте шаг времени
или уменьшите длину преобразования/верхнюю частоту.

## FFT и прямое ДПФ

При длине преобразования M, равной степени двойки, используется FFT.
Иначе вычисляется напрямую:

```text
X[k] = Σ(j=0..N−1) x[j] · w[j] · (cos(2πkj/M) − i·sin(2πkj/M))
P[k] = |X[k]|² / Σ w[j]²
f[k] = k · Fs/M,  k = 0 .. floor(M/2)
```

N — число отсчётов сигнала в окне, w — выбранная оконная функция.
Для нескольких каналов усредняются мощности. При M=N преобразование не
дополняет сигнал нулями. M>N означает явно запрошенное дополнение нулями.
Чётная длина включает бин Nyquist; при нечётной последний бин ниже Nyquist.
Прямое ДПФ медленнее FFT. Команда **To SpectrogramS…** показывает прогресс
и допускает отмену. Автоматический анализ в редакторе, как и обычный анализ
Praat, выполняется при перерисовке без отдельного окна прогресса; для больших
окон удобнее заранее создать объект и открыть его вместе со звуком.

Например, `To SpectrogramS: 300, 75, 5000, 0, "Gaussian"` использует ДПФ
длиной 300, а длина 256 с нулём в четвёртом поле — FFT длиной 256.
В **Info** и **Get transform method** можно проверить использованный метод.

## Преобразования без пересчёта

- **SpectrogramS → To Spectrogram**: копируются все значения и обе оси,
  без изменения разрешения или уровней.
- **Spectrogram → To SpectrogramS…**: укажите частоту дискретизации источника.
  Исходную длину окна можно указать либо оставить **0 = unknown**; форма окна
  задаётся как метаданные. Шаг в отсчётах определяется по временной оси.

Обычный Spectrogram не хранит исходные Fs, длину и форму окна или размер FFT.
Восстановить их достоверно только по матрице нельзя. Поэтому обратное
преобразование явно запрашивает метаданные и не выдаёт их за новый анализ.
При неизвестной длине её значение в миллисекундах — undefined, длина преобразования
после такого преобразования — 0. Матрица и временная/частотная сетки
при обоих преобразованиях сохраняются точно. Для сохранения всех параметров
между сеансами используйте нативный SpectrogramS.

Готовый пример: `scripts/sample-count-spectrogram-demo.praat`
(в сборке — `examples/sample-count-spectrogram-demo.praat`). Он создаёт
тестовый звук и открывает его вместе с SpectrogramS; длина 300 выбирает ДПФ.

## Пример Praat

```praat
Read from file: "recording.wav"
# Пример для звука с Fs не ниже 10000 Гц:
To SpectrogramS: 256, 64, 5000, 512, "Gaussian"
Get analysis length in milliseconds
Save as binary file: "recording.SpectrogramS"
To Spectrogram
# Здесь Fs=22050 известно из исходной записи:
To SpectrogramS: 22050, 256, "Gaussian"
```

Lua вызывает эти же команды через `praat.call("To SpectrogramS", ...)`.
Порядок аргументов совпадает с формами выше; для обратного преобразования
первый аргумент — Fs, а не длина окна.

## Проверки

`tests/spectrogram-s/test.praat` проверяет тон на точном FFT-бине, размеры
окон и шаг, нечётное окно с импульсами на границе, независимую нормировку
Gaussian, противоположные фазы стереоканалов, все ячейки преобразования туда
и обратно, текстовое/бинарное сохранение и неправильные параметры.
Отдельно сравниваются все бины FFT и прямого ДПФ с независимой формулой
для нечётных длин, явного дополнения нулями и чётной длины 18 с бином Nyquist.
`tests/spectrogram-s/gui.praat` проверяет публикацию из Sound Editor,
совпадение кадров после Zoom, прямое ДПФ в редакторе, спектральный срез,
возврат к секундам и отдельное/совместное открытие.
